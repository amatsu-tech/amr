# amr

[English](README.md) | Русский

**amr** (Amatsu multi-repo) — консольная утилита, которая помогает работать со многими Git-репозиториями как с одним рабочим пространством (workspace).

Склонировать все репозитории одной командой, увидеть состояние каждого, обновить всё сразу или выполнить команду во всех репозиториях.

> Утилита в разработке. До версии 1.0 команды и формат конфига могут меняться.

## Быстрый старт

```bash
cd ~/projects/my-company
amr init        # создать workspace в этой папке
amr scan        # найти Git-репозитории, в том числе во вложенных папках, например services/api
amr add --all   # добавить все найденные репозитории
amr status      # ветка и изменения в каждом репозитории
```

Как поделиться workspace с командой и получить ту же структуру папок на любой машине — в разделе [Workspace для команды](#workspace-для-команды).

## Что такое workspace

Workspace — это папка, внутри которой лежат твои репозитории, а в корне есть служебная папка `.amr` с конфигом. Например:

```
my-company/
├── .amr/amr.yaml      ← список репозиториев и их адреса
├── frontend/
├── infra/
└── services/
    ├── api/
    └── billing/
```

Все команды, кроме `init`, можно запускать из любой папки внутри workspace: `amr` сам поднимется вверх и найдёт `.amr`.

## Команды

| Команда | Что делает |
| --- | --- |
| `amr init [папка]` | Создать workspace в текущей или указанной папке |
| `amr scan` | Найти Git-репозитории в workspace и показать, какие уже добавлены |
| `amr add [<путь>...]` | Добавить репозитории в workspace (пути относительно текущей папки). `--all` добавляет все найденные, `-g` сразу записывает их в группу |
| `amr remove <путь>...` | Убрать репозитории из workspace (файлы на диске остаются) |
| `amr list` | Показать добавленные репозитории и их группы |
| `amr clone` | Склонировать репозитории, которых нет на диске |
| `amr status` | Показать ветку и изменения в репозиториях |
| `amr pull` | Подтянуть изменения в репозитории без локальных правок (только fast-forward) |
| `amr sync` | Обновить конфиг workspace (если это Git-репозиторий), склонировать недостающее и подтянуть остальное |
| `amr run -- <команда>...` | Выполнить команду в репозиториях |
| `amr root` | Показать путь к корню workspace |

Подробности по каждой команде: `amr <команда> --help`.

## Как выбрать репозитории

`list`, `clone`, `status`, `pull`, `sync` и `run` по умолчанию работают со всеми репозиториями. Чтобы работать только с частью, укажи пути или группы:

```bash
amr pull frontend services/api        # только эти репозитории
amr pull -g backend                   # репозитории из группы backend
amr pull -g backend,web               # из любой из этих групп (или -g backend -g web)
amr pull infra -g backend             # путь и группа вместе
amr run -g backend -- go test ./...   # в run пути и группы пишутся до --
```

Если указать и пути, и группы, берутся все подходящие репозитории: и указанные путём, и входящие в группу. Порядок — как в конфиге, без повторов.

Если такого пути или группы нет в конфиге, например из-за опечатки, команда ничего не делает и сразу показывает ошибку:

```
$ amr pull -g bakend
Error: no repositories in group: bakend
```

Группы задаются при добавлении (`amr add -g backend services/api`) или прямо в конфиге.

## Параллельная работа

`clone`, `status`, `pull`, `sync` и `run` обрабатывают до 8 репозиториев одновременно. Это меняется флагом `--jobs` (`-j`):

```bash
amr pull -j 16          # быстрее, если репозиториев много
amr run -j 1 -- make    # строго по одному
```

Пока идут `pull`, `clone` и `sync`, в терминале видна строка прогресса. Если вывод перенаправлен в файл или в другую команду (`amr pull | grep ...`), прогресса и цветов нет, остаётся только чистый текст результата.

## Конфиг workspace

Конфиг лежит в `.amr/amr.yaml`. Его заполняет `amr add` и берёт адрес из `origin` каждого репозитория:

```yaml
version: 1
repositories:
  - path: frontend
    url: git@github.com:your-org/frontend.git
  - path: services/api
    url: git@github.com:your-org/api.git
    groups: [backend]
```

| Поле | Значение |
| --- | --- |
| `path` | путь от корня workspace, можно вложенный |
| `url` | адрес для клонирования |
| `groups` | группы, необязательно |

Репозиторий без `origin` сохраняется без `url`, и `amr clone` его пропускает.

Конфиг можно править руками, например, чтобы поменять путь или группы.

## Workspace для команды

Конфиг удобно хранить в отдельном Git-репозитории, например `your-org/acme-workspace`. Название может быть любым.

`amr init` сам создаёт `.gitignore`, чтобы в этот репозиторий попадал только конфиг, а не склонированные репозитории. Если в папке уже есть `.gitignore` или она сама является Git-репозиторием, файл не создаётся:

```gitignore
/*
!/.amr/
!/.gitignore
!/README.md
```

Новый человек в команде получает всю структуру тремя командами:

```bash
git clone git@github.com:your-org/acme-workspace.git acme
cd acme
amr sync
```

Дальше достаточно время от времени запускать `amr sync`. Он сначала обновляет сам конфиг, поэтому репозитории, которые добавили коллеги, тоже склонируются.

## Разработка

Нужны Go и [Task](https://taskfile.dev).

```bash
task run -- --help   # запустить из исходников
task build           # собрать бинарник в build/amr
task check           # форматирование, зависимости, сборка, тесты
task test            # запустить тесты
task bench           # запустить бенчмарки
```
